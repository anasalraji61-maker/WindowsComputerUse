# Prompt — الصقه في ChatGPT / Claude / منصة فحص روبوتات

أنت مستشار تقني خبير في:
1) أنظمة أتمتة سطح المكتب (Windows computer-use agents)
2) QuantConnect / LEAN backtesting
3) روبوتات فوركس متعددة الرموز (ensemble / risk / council)

اقرأ الملفات المرفقة في حزمة الاستشارة ثم أجب بالعربية الفصحى الواضحة.

## السياق المختصر
- المستخدم يريد روبوتاً/نظاماً ينفّذ أوامره بفعالية.
- بُني نظام اسمه COS/APOS على Windows يحاول التحكم بالماوس والمتصفح والصوت.
- هذا المسار فشل عملياً (بطء، تقارير بدل تنفيذ، اعتماد على واجهة QuantConnect البصرية).
- يوجد روبوت تداول `MatrixRobotQC` (ملف Python واحد، class `MatrixRobotQC(QCAlgorithm)`) جاهز لفحصه على QuantConnect.
- بدأنا منفّذاً جديداً: رفع الكود عبر QuantConnect REST API → Compile → Backtest → تقرير إحصائيات (بلا ماوس).
- ينقص فقط `QC_USER_ID` + `QC_API_TOKEN` لتشغيل أول Backtest حقيقي.

## أريد منك
1. تقييماً صادقاً: هل مسار الوكيل العام على Windows يستحق المتابعة أم يجب إيقافه؟
2. أفضل مسار عملي خلال 7–14 يوماً للحصول على نتائج رقمية من فحص الروبوت.
3. مراجعة منهجية لكود `MatrixRobotQC` (مخاطر، أخطاء شائعة في QC، بيانات OANDA، overfitting، اقتراحات اختبار).
4. مقارنة خيارات الفحص: QuantConnect Cloud API vs Lean CLI vs منصات أخرى (StrategyQuant / local vectorbt / إلخ) لهذا الروبوت تحديداً.
5. خطة معمارية بسيطة: «فاهم أوامر» + «منفّذون متخصصون» — بدون مبالغة.
6. قائمة تحقق (checklist) قبل أول Backtest سحابي ناجح.
7. ما الذي يجب أن يبقى بشرياً (تسجيل دخول، 2FA، قرارات رأس مال) وما يمكن أتمتته بأمان.

## قيود مهمة
- لا تفترض أن لدينا نتائج Backtest سابقة موثوقة من مسار الماوس.
- لا تقترح إعادة بناء «وكيل يتحكم بكل Windows» كحل أول.
- كن محدداً بخطوات وملفات ومقاييس نجاح (Sharpe / Drawdown / عدد الصفقات / استقرار عبر فترات).

ابدأ بتقييم تنفيذي في صفحة واحدة، ثم التفاصيل.
