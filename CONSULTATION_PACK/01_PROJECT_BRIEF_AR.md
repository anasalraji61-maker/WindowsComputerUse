# ملخص المشروع للاستشارة (عربي)

## 1) ماذا نبني؟
نظامان مرتبطان:

### أ) COS / APOS — أتمتة Windows
المجلد: `WindowsComputerUse/APOS`
- واجهة دردشة عربية + صوت (STT/TTS سحابي)
- عقل سحابي (OpenRouter / GPT-4o-mini)
- محاولة تنفيذ عبر الماوس/لوحة المفاتيح/المتصفح
- دورة قديمة `matrix_cycle.yaml`: إيجاد ملف → فتح QuantConnect في المتصفح → لصق → Backtest بالنقر

**الواقع:** هذا المسار غير موثوق. يظهر غالباً كحركة ماوس أو تقارير بدل نتيجة رقمية.

### ب) MatrixRobotQC — روبوت الفحص على QuantConnect
المسار المفضل:
`MatrixRobot_Handoff_Clean-3/.../quantconnect/MatrixRobotQC/main.py`

- ملف واحد (~770 سطر)
- `class MatrixRobotQC(QCAlgorithm)`
- رموز فوركس + معادن عبر `Market.OANDA` بدقة ساعة
- فترة افتراضية تقريباً 2023→2024
- طبقات: ensemble, ICT, session, council, risk, prop, emergency, correlation, scalp-simplified
- **غير موجود في QC:** جسر MT5، عقل GPT الحي، سجلات VPS

## 2) القرار الحالي (مهم)
إيقاف الاعتماد على «وكيل عام يحرّك الشاشة» كمسار أساسي.

البديل: **منفّذون متخصصون**. الأول جاهز كوداً:

`APOS/cos/execution/qc_executor.py`

التدفق:
1. قراءة `main.py`
2. مصادقة QuantConnect API (`QC_USER_ID` + `QC_API_TOKEN`)
3. إنشاء/تحديث مشروع `MatrixRobotQC`
4. Compile
5. Backtest
6. حفظ تقرير في `APOS/data/reports/QC_API_*.md`

تشغيل سريع: `RUN_QC_BACKTEST.bat`

## 3) ما يعمل / ما لا يعمل

| العنصر | الحالة |
|--------|--------|
| ملف روبوت QC موجود | نعم |
| منفّذ API مكتوب ومربوط بالمخطّط | نعم |
| مفاتيح QC في `.env` | **لا — ناقصة** |
| أول Backtest رقمي عبر API | لم يُنفَّذ بعد بسبب المفاتيح |
| وكيل الماوس العام | ضعيف — لا يُعتمد عليه |
| صوت/شات عربي | يعمل جزئياً؛ ليس مقياس النجاح |

## 4) لماذا «فشل» مسار الروبوت المستقل؟
1. هدف فضفاض (سمع + فهم + ماوس + QC + تقارير…)
2. التنفيذ البصري هش
3. خلط الفهم مع التنفيذ
4. غياب مقياس نجاح رقمي مبكر
5. حدود بشرية (Login/2FA) لا تُلغى بأوهام الأتمتة الكاملة
